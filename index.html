About

A QA engineer who treats testing as risk management, not a checklist.

I started in manual QA and quickly gravitated toward the edges — offline states, race conditions, multiple concurrent SOS sessions, the scenarios that don't show up in a happy-path demo. That instinct is what I bring to every release: find what's actually going to break in production, before it does.

I work across mobile apps, wearables and the APIs underneath them, moving comfortably between the UI in front of a user and the request/response behind it. I'm also deliberately building DevOps skills — Linux, Git workflows, CI/CD — because the QA engineers I respect most understand the pipeline their tests run in, not just the app on screen.

Full ownership of the QA cycle — design, execute, report, retest

Edge-case instinct
